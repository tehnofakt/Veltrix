# Veltrix

Один Telegram-бот на сервере для нескольких пользователей. Пользователь нажимает **Start**, получает инструкцию и самостоятельно подключает бота к выбранным личным чатам через **Автоматизацию чатов / Secretary Mode** в настройках Telegram. Номер телефона, код входа, пароль, `API_ID` и `API_HASH` передавать боту не нужно.

Python 3.11+, aiogram, SQLite. Интерфейс и архив находятся в Telegram. Веб-панелей, Docker и платежей нет. Подписки и оплата в это обновление не входят.

## Обновление интерфейса и архива

- Главное меню: **Переписки / Настройки / Подключение / Помощь**. Диалоги выбираются по имени кнопками, технические ID в обычном интерфейсе не показываются.
- Удаления и редакции оформлены компактными карточками с именем отправителя, цитатой и кнопкой открытия сохранённой переписки. Если за одно событие удалено несколько сообщений, приходит одна карточка.
- Telegram не сообщает, **кто именно удалил** сообщение. Карточка показывает отправителя сохранённого сообщения, а не предполагаемого инициатора удаления.
- Сохраняются **обе стороны новой переписки**: входящие, исходящие, сообщения, отправленные ботом от имени пользователя, и версии изменённого текста. Собственные редакции сохраняются без лишнего уведомления.
- Удаление оригиналов, включая массовое удаление сообщений, не удаляет локальный архив. Он остаётся доступен через «Переписки».
- Кнопка **«Скачать всю переписку»** присылает ZIP: читаемый HTML с хронологией, отметками об удалении, историей редакций и сохранёнными фотографиями. Файл открывается без подключения к Veltrix. Если фото не помещаются в один файл для Bot API, присылается весь текст в HTML, фотографии остаются доступны в боте.

**«Вся переписка» означает все события, которые Veltrix успел получить после подключения.** Bot API не предоставляет выгрузку старой истории. Ранее удалённые или пропущенные сообщения восстановить нельзя. Уведомление о массовом удалении само по себе не доказывает удаление всего чата.

## Мут и скорость

### Мут

В подключённой переписке отправьте `.mute`, для отключения — `.unmute`. Также есть кнопка мута внутри сохранённой переписки. Настройка сохраняется после перезапуска.

В «Настройках» доступны два режима:

| Режим | Что происходит |
| --- | --- |
| **Быстрый** — по умолчанию | Текст, отправитель и `file_id` фотографии фиксируются в SQLite, затем сразу запускается запрос удаления. Скачивание фото идёт в фоне и не задерживает удаление или обработку других чатов. Локальная копия фото в этот момент ещё может отсутствовать. |
| **Сначала сохранить фото** | Сначала скачивается обычная фотография на сервер, затем запускается удаление. Если после повторных попыток фото сохранить не удалось, оригинал остаётся на месте. Этот режим медленнее. |

У мута нет дополнительного таймера задержки. Запросы удаления отделены от отправок и скачивания медиа: ожидание `sendMessage` не создаёт искусственную паузу перед `deleteBusinessMessages`. Каждый полученный `retry_after` соблюдается для соответствующей операции. Нулевую задержку гарантировать нельзя: есть время доставки события, записи в базу, сети и обработки запроса Telegram. Сообщение может успеть появиться у пользователя или в уведомлении Telegram.

Перед собственным запросом удаления ставится постоянная отметка. Удаления мутом не создают уведомлений об удалении, но доступны в архиве. В быстром режиме получение фотографии после удаления не гарантировано; `file_id` и подпись сохраняются до запроса. Фоновые загрузки восстанавливаются после перезапуска. При неоднозначном сетевом результате отметка собственного запроса остаётся, чтобы не сообщать о нём как о чужом удалении.

### Отправка

```text
.spam 10 привет
.stopspam
.speed 0.1
```

Количество — любое положительное целое, без ограничения в 10. Каждое сообщение отправляется отдельным последовательным запросом. В «Настройках» можно выбрать свою дополнительную паузу: **0 / 0.1 / 0.3 / 1 секунда**. Команда `.speed` принимает и другие конечные неотрицательные значения. Настройка индивидуальна для пользователя и сохраняется в SQLite.

**0 убирает только дополнительный таймер**, а не время API-запроса и ограничения Telegram. При `429` отправка ждёт полный `retry_after`. Запросы не распараллеливаются ради обхода лимитов, токены или аккаунты не переключаются. Сетевая ошибка с неизвестным результатом останавливает отправку, чтобы не повторить сообщение вслепую. `.stopspam` прерывает задачу, в том числе ожидание. После перезапуска активные отправки не возобновляются.

В диалоге с самим Veltrix доступны безопасные тесты от имени бота:

```text
.spam 10 тест
.spam forever тест
.stopspam
```

Бесконечная отправка в подключённые переписки запрещена; она разрешена только в собственном диалоге с Veltrix. [Telegram рекомендует](https://core.telegram.org/bots/faq#my-bot-is-hitting-limits-how-do-i-avoid-this) избегать отправки чаще одного сообщения в секунду в один чат: быстрые короткие серии могут пройти, но устойчивую повышенную скорость обещать нельзя.

## Ограничения доступа Telegram

- Нажатие `/start` не даёт доступа к перепискам. Пользователь должен отдельно подтвердить подключение, чаты и права в настройках Telegram.
- Работа ведётся в выбранных **личных облачных чатах**. Группы, каналы, секретные чаты и «Избранное» эта версия не обслуживает.
- Для отправки и редактирования от имени пользователя требуется `can_reply`. Telegram ограничивает эти действия чатами с входящими сообщениями за последние 24 часа. Отдельный запрос всё равно может быть отклонён сервером.
- Для удаления входящих необходимо `can_delete_all_messages`. Применяется `deleteBusinessMessages`, с его ограничениями по возрасту и типу сообщений. Отдельного параметра `revoke=False` у Bot API нет.
- Команды с точкой выполняются только от владельца соответствующего подключения. Команды от собеседника не управляют ботом. Собственные сообщения, отправленные механизмом повторения, повторно команды не запускают.
- При успешном выполнении команда редактируется: `🔇 Мут активирован`, `🔊 Мут отключён`, `✅ Запущена отправка N сообщений`. Если Telegram не даёт её отредактировать, результат приходит в диалог с Veltrix.
- Локально скачиваются обычные фотографии. Одноразовое, самоуничтожающееся и защищённое медиа не копируется. Для остальных вложений сохраняются текст/подпись и отметка о вложении, но не сам файл. Полный архив видео, файлов и голосовых не заявляется.
- Получение всех событий и доставка каждого уведомления не гарантированы. У Telegram ограниченный срок хранения обновлений — до 24 часов. Авария после подтверждения обновления и до локальной записи может привести к пропуску. При аварии между доставкой уведомления и фиксацией результата возможен дубль.

Источники: [Business Bots](https://core.telegram.org/bots/features#business-bots), [права бота](https://core.telegram.org/bots/api#businessbotrights), [удаление](https://core.telegram.org/bots/api#deletebusinessmessages), [получение обновлений](https://core.telegram.org/bots/api#getting-updates). Согласно [текущей документации](https://core.telegram.org/api/bots/connected-business-bots), подключение бота не требует Premium. Названия пунктов настроек зависят от клиента Telegram.

## Подготовка бота

1. Создайте бота через [@BotFather](https://t.me/BotFather) или используйте уже имеющийся.
2. В настройках именно этого бота включите **Secretary Mode / Business Mode**.
3. Создайте на сервере `.env` по примеру `.env.example`:

```dotenv
BOT_TOKEN=ВАШ_ТОКЕН_ИЗ_BOTFATHER
SPAM_DELAY=0.1
```

`SPAM_DELAY` задаёт начальную паузу для пользователей без индивидуальной настройки. Поддерживается `0`. Уже заполненный `.env` автоматически не перезаписывается: если там осталось `1.5`, выберите меньшую паузу в интерфейсе или измените файл. Настоящий токен должен быть только в `.env`, **никогда не в `.env.example`**.

## Запуск на Windows

Установите Python 3.11+ и Git. В PowerShell:

```powershell
git clone https://github.com/tehnofakt/Veltrix.git
cd Veltrix
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
.\.venv\Scripts\python.exe main.py
```

Не нужно активировать окружение или менять Execution Policy. Остановка — `Ctrl+C`.

## Запуск на Linux-сервере

```bash
git clone https://github.com/tehnofakt/Veltrix.git
cd Veltrix
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
nano .env
chmod 600 .env
.venv/bin/python main.py
```

Понадобятся Python 3.11+ и поддержка `venv`. Для постоянного запуска используйте отдельного системного пользователя и systemd. Пример `/etc/systemd/system/veltrix.service` — замените пользователя и пути:

```ini
[Unit]
Description=Veltrix Telegram bot
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=veltrix
WorkingDirectory=/home/veltrix/Veltrix
ExecStart=/home/veltrix/Veltrix/.venv/bin/python -u /home/veltrix/Veltrix/main.py
Restart=on-failure
RestartSec=5
UMask=0077

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now veltrix
sudo systemctl status veltrix
```

Long polling не требует домена и входящего порта. Нужен исходящий доступ к Telegram. При запуске прежний webhook снимается без удаления ожидающих обновлений. Один токен обслуживается одним экземпляром программы. Сетевые сбои polling обрабатывает с переподключением.

## Обновление существующего сервера

1. Остановите старую программу / сервис.
2. Скопируйте всю папку `data` в защищённое место вне Git как резервную копию.
3. Выполните `git pull --ff-only`, затем установку `-r requirements.txt` из своего виртуального окружения.
4. Сохраните существующий `.env`; при необходимости измените `SPAM_DELAY`.
5. Запустите бота и отправьте `/start`, чтобы обновить меню Telegram.

Схема `data/veltrix.sqlite3` обновляется автоматически без удаления старого архива и мута. Входящие из прежней версии сохраняются; исходящие, которые старая версия не записала, восстановить невозможно. Файл `data/archive.sqlite3` от первоначального Telethon-юзербота не мигрируется. После миграции откат к старому коду требует восстановления совместимой резервной копии.

## Управление и хранение

В меню доступны список диалогов, просмотр истории, фотографии, переключатель мута и экспорт. В переписке работают `.mute`, `.unmute`, `.spam`, `.stopspam`, `.speed`, `.help`. Сохраняется совместимость с `/mute ID`, `/unmute ID`, `/spam ID количество текст`, `/stopspam ID` для знающих ID своих чатов; обычному пользователю вводить их не нужно.

`/status` показывает подключение и права. `/stop` приостанавливает обработку, уведомления и свои фоновые операции. `/start` возобновляет. `/erase confirm` останавливает обработку, удаляет свой серверный архив, очередь, версии текста, фотографии, временные экспорты и настройки. Уже отправленные сообщения Telegram, резервные копии и блоки диска гарантированно не стираются. Минимальный ID пользователя с флагом остановки остаётся для защиты от запоздалых событий. Подключение нужно также отозвать в Telegram.

База и фотографии находятся на вашем сервере в `data/veltrix.sqlite3` и `data/media/`. Временные экспорты создаются в `data/exports/` и удаляются после отправки. В GitHub и внешние хранилища программа переписки не отправляет. Уведомления и архивы в диалоге с ботом хранятся также в облаке Telegram. Владелец сервера технически имеет доступ к SQLite и файлам, прикладного шифрования нет. Ограничьте права на `.env`, `data` и резервные копии. Автоматической очистки архива по сроку нет — следите за местом на диске.

`.gitignore` исключает конфигурацию с ключами, базы, медиа, логи, сессии, экспорты и окружения. Не используйте `git add -f` для этих файлов. Перед публикацией проверяйте `git diff --cached --name-only`.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m compileall -q main.py storage.py interface.py tests
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m pip check
```

Автоматические тесты используют реальные модели и диспетчер aiogram, временную SQLite-базу и имитацию API. Проверяются права и изоляция пользователей, callbacks, мут при задержанной загрузке фото и ограничении отправки, оба режима мута, нулевая пауза и остановка, история обеих сторон, массовое удаление, очередь уведомлений, миграция старой базы, экспорт и экранирование пользовательского HTML.

Эти проверки не подтверждают фактическое время удаления в Telegram или коммерческую готовность под реальной нагрузкой. Проверка с подключёнными аккаунтами и нагрузкой выполняется на вашем сервере до продажи доступа. Минимальный ручной сценарий: `/start` → подключение → `/status` → входящее/исходящее/фото → изменение и удаление → просмотр всей переписки и экспорт → оба режима мута → конечная отправка и остановка → отзыв доступа.
