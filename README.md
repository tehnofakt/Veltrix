# Veltrix

Минимальный Telegram-юзербот на Python 3.11+, Telethon и SQLite. Работает через **личный аккаунт**, команды принимает только от его владельца. BotFather и токен бота не нужны.

## Запуск на Windows

Нужны Python 3.11+ с [python.org](https://www.python.org/downloads/windows/) и Git. В PowerShell:

```powershell
git clone https://github.com/tehnofakt/Veltrix.git
cd Veltrix
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
```

Получите собственные `api_id` и `api_hash` на [my.telegram.org/apps](https://my.telegram.org/apps) и заполните `API_ID`, `API_HASH` в `.env`. `PHONE` необязателен: номер можно ввести при запуске. `SPAM_DELAY` — пауза между сообщениями в секундах, минимум 1, по умолчанию 1.5.

```powershell
.\.venv\Scripts\python.exe main.py
```

При первом запуске введите номер телефона с кодом страны, код авторизации Telegram и пароль двухэтапной аутентификации, если он включён. Вводите их **только локально в терминале**. Далее используется сохранённая сессия. Активация виртуального окружения и изменение политики PowerShell не требуются.

После надписи «Veltrix запущен» отправьте `.help` в Telegram. Остановка программы — `Ctrl+C`. Запускайте только один экземпляр с одной сессией. При обычном разрыве сети Telethon переподключается автоматически. После отзыва сессии или неисправимой ошибки запустите программу снова; при необходимости повторите вход.

## Команды

| Команда | Действие |
| --- | --- |
| `.spam 10 привет` | Отправляет 10 отдельных сообщений `привет` в текущий чат. Можно указать любое положительное целое количество. |
| `.spam forever привет` | Непрерывное повторение до остановки, **только в «Избранном»**. |
| `.stopspam` | Останавливает отправку в текущем чате, в том числе во время ожидания FloodWait. |
| `.mute` | Сохраняет и удаляет новые сообщения собеседника в текущем личном чате. |
| `.unmute` | Отключает мут в текущем личном чате. |
| `.help` | Показывает справку. |

Исходные команды редактируются: `.mute` → `🔇 Мут активирован`, `.unmute` → `🔊 Мут отключён`, `.spam 10 привет` → `✅ Запущена отправка 10 сообщений`. Сообщения с текстом команд, отправленные самим механизмом повторения, повторно команды не запускают.

В одном чате работает одна отправка; в разных чатах можно запускать отдельно. Перезапуск отменяет отправки, но сохраняет настройки мута. Мут действует только на **новые входящие**; старую историю он не удаляет. В группах, каналах и «Избранном» мут недоступен.

FloodWait и SlowModeWait соблюдаются полностью, с небольшой дополнительной паузой. Ожидание общее для операций юзербота; подтверждение команды тоже может задержаться. Фиксированная пауза не гарантирует отсутствие ограничений: лимиты Telegram меняются в зависимости от аккаунта и действий. Используйте повторение для своих тестов и согласованных сообщений. Veltrix не обходит ограничения Telegram. [Обработка RPC-ошибок в Telethon](https://docs.telethon.dev/en/stable/concepts/errors.html).

## Архив

При работающем Veltrix новые входящие сообщения **личных облачных переписок** сохраняются в `data/archive.sqlite3`, обычные фотографии — в `data/media/`. В SQLite хранятся ID сообщения и чата, имя и ID отправителя, дата, текст/подпись, путь к фотографии и служебные флаги.

При событии удаления Veltrix отправляет в «Избранное» имя отправителя, сохранённый текст и фотографию, если она была скачана. При изменении текста или подписи показывает предыдущую и новую версии. Архив хранит последнюю известную версию; полная история редакций отдельно не ведётся. Длинные уведомления разбиваются на несколько сообщений.

При муте запись сохраняется **до удаления**, сначала запрашивается `revoke=True`. Если Telegram явно запрещает такое удаление, выполняется попытка `revoke=False`. Если сохранить обычную фотографию не удалось, сообщение не удаляется, а текст остаётся в базе. Собственные удаления мута помечаются в SQLite заранее и не создают уведомлений, включая после перезапуска.

Ограничения:

- Telegram не гарантирует события для всех удалений. При событии удаления в личном чате ID чата может отсутствовать; Veltrix сопоставляет его с заранее сохранённым ID сообщения. [Документация MessageDeleted](https://docs.telethon.dev/en/stable/modules/events.html#telethon.events.messagedeleted.MessageDeleted).
- История до запуска не загружается. Сообщения, изменения и удаления за время остановки программы не восстанавливаются гарантированно.
- Одноразовые и самоуничтожающиеся медиа не скачиваются. Секретные чаты не поддерживаются. Для видео, голосовых, файлов и других медиа сохраняются только текст/подпись и отметка о типе вложения.
- Если фото удалили до завершения скачивания, восстановить его невозможно. Если потеряна папка `data`, исчезнет и локальный архив.
- Ошибка обработчика выводится в терминал по имени класса, без текста переписки. Неисправимые ошибки отправки останавливают соответствующую задачу. Повторная доставка неудавшегося уведомления после перезапуска не гарантируется.
- Если результат собственного запроса удаления неизвестен из-за разрыва сети или отмены, отметка сохраняется. Для этого сообщения последующее событие удаления не создаст уведомления.

## Личные данные и Git

`.gitignore` исключает `.env`, папку `data`, Telegram-сессии и их вспомогательные файлы, SQLite-базы, фотографии, логи и виртуальное окружение. В репозиторий добавляются только код, тесты, зависимости, инструкция и `.env.example` с фиктивными значениями. Сессия и архив хранятся локально без дополнительного шифрования: доступ к файлу сессии даёт доступ к аккаунту. Не передавайте его другим людям.

Проверить состав будущего коммита:

```powershell
git status --short
git diff --cached --name-only
```

Для дополнительной копии архива остановите программу и скопируйте всю папку `data` в защищённое локальное место, вне Git. Автоматической очистки архива нет.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m compileall -q main.py tests
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты используют временную SQLite-базу и имитацию Telegram API: проверяют команды владельца, отправку и остановку, FloodWait, сохранение мута, архивирование фото, редакции и исключение собственных удалений. Реальный вход и взаимодействие с Telegram проверяются после локальной настройки `.env`.
