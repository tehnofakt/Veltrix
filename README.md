# Veltrix

Один Telegram-бот на вашем сервере для нескольких пользователей. Пользователь нажимает **Start**, получает инструкцию и подключает бота к выбранным личным чатам в настройках Telegram. Устанавливать Python, получать `API_ID` / `API_HASH` или передавать боту код входа пользователю не нужно.

Это серверная версия на **Python 3.11+, aiogram и SQLite**, работающая через официальный Bot API и подключение **Secretary Mode / Business Mode**. Она заменяет прежний локальный Telethon-юзербот. Docker, веб-панели и платежей нет.

## Что работает и где границы

| Возможность | Поведение |
| --- | --- |
| Подключение пользователей | `/start` → инструкция → пользователь сам выбирает бота, чаты и права в Telegram. Сам `/start` доступа к переписке не даёт. |
| Отправка | `.spam N текст` в подключённой переписке или `/spam ID N текст` в диалоге с Veltrix. Любое положительное целое N, отдельными сообщениями. |
| Остановка | `.stopspam` в переписке, `/stopspam ID` в боте. Отменяет отправку, включая ожидание ограничения. Уже отправленное не удаляется. |
| Непрерывный тест | `.spam forever текст` разрешён **только в личном диалоге с Veltrix**, сообщениями от бота. В подключённых переписках запрещён. |
| Мут | `.mute` / `.unmute` в подключённом личном чате либо `/mute ID` / `/unmute ID` в боте. Настройка сохраняется после перезапуска. |
| Архив | Новые входящие сообщения доступных личных чатов сохраняются в SQLite, обычные фотографии — локально на сервере. `/archive` показывает собственный архив в боте. |
| Удаления | Когда Telegram присылает событие удаления, в диалог с Veltrix приходит сохранённый текст, имя отправителя и локальная фотография, если она успела скачаться. |
| Изменения | При изменении текста или подписи приходит предыдущая и новая версия. В основной записи архива остаётся последняя версия; тексты уведомлений тоже сохраняются на сервере. |
| Собственные удаления | Перед удалением мутом ставится постоянная отметка; уведомления об этих удалениях не отправляются. Сообщения остаются доступны через `/archive`. |
| Команды владельца | Команды в переписке выполняются только от владельца соответствующего подключения. Слова `.mute` от собеседника командой не считаются. |
| Разделение данных | Записи, настройки и запросы архива привязаны к ID пользователя. Пользователь не может указать чужой ID владельца для чтения архива или управления чатами. |

Bot API не даёт полных возможностей личной Telegram-сессии. **Нельзя честно обещать работу во всех чатах без ограничений.**

- Доступны только личные чаты, выбранные пользователем в настройках подключения. Группы, каналы, секретные чаты и «Избранное» эта версия не обслуживает.
- Для отправки и редактирования от имени пользователя нужно право `can_reply`. Telegram ограничивает такие действия чатами, где были входящие за последние **24 часа**. Даже если право выдано, конкретный запрос может быть отклонён Telegram.
- Для удаления входящих нужно `can_delete_all_messages`. Используется `deleteBusinessMessages`: отдельного переключателя `revoke=True/False` у этого метода нет. Действуют ограничения Bot API на удаление, включая возраст сообщения и отдельные типы сообщений. Ошибка удаления не выдаётся за успех.
- Команда в переписке редактируется в подтверждение (`🔇 Мут активирован`, `🔊 Мут отключён`, `✅ Запущена отправка N сообщений`), если Telegram позволяет. При отказе результат приходит в личный диалог с Veltrix. Бот не может редактировать ваши обычные сообщения в диалоге с самим ботом: там он отвечает отдельно.
- Старую историю Bot API не выгружает. Архив начинается после `/start`, подключения и получения новых событий. Неизвестное боту удалённое сообщение восстановить нельзя.
- Одноразовые и секретные медиа не поддерживаются. Защищённые фотографии не копируются. Для остальных вложений сохраняются текст/подпись и отметка, но не сам файл. Если обычное фото не скачалось, текст сохраняется, а мут это сообщение не удаляет.
- Частота регулируется `SPAM_DELAY` и ответами Telegram `429 / retry_after`. Полученные ожидания соблюдаются полностью, с дополнительной секундой; пауза общая для бота. Это не обход лимитов и не гарантия, что ограничений не будет.
- При неопределённом сетевом результате отправка останавливается, чтобы не повторять сообщение вслепую. Последнее сообщение могло дойти без подтверждения. Активные отправки после перезапуска не возобновляются.
- Уведомления ставятся в постоянную SQLite-очередь и повторяются после временной ошибки. При аварии между успешной отправкой и записью результата возможен дубль. Абсолютная доставка каждого события не гарантируется. Очередь Telegram тоже имеет ограниченный срок хранения (обычно до 24 часов).
- После неоднозначного сбоя удаления сохраняется отметка собственного запроса. Последующее событие удаления этого сообщения не вызовет уведомления. Отключение мута влияет на новые сообщения; уже начатый запрос может успеть завершиться.

Описание подключения и прав: [Telegram — Business Bots](https://core.telegram.org/bots/features#business-bots), [BusinessBotRights](https://core.telegram.org/bots/api#businessbotrights), [deleteBusinessMessages](https://core.telegram.org/bots/api#deletebusinessmessages). По текущей документации [подключение бота не требует Premium](https://core.telegram.org/api/bots/connected-business-bots). Расположение настроек и названия пунктов зависят от версии клиента.

## Подготовка владельцем бота

1. Создайте бота в [@BotFather](https://t.me/BotFather) или используйте уже созданного.
2. В настройках этого бота в BotFather включите **Secretary Mode / Business Mode**. Обычного токена без включённого режима недостаточно для подключения чужих аккаунтов.
3. На сервере создайте `.env` по примеру `.env.example` и вставьте свой токен:

```dotenv
BOT_TOKEN=ВАШ_ТОКЕН_ИЗ_BOTFATHER
SPAM_DELAY=1.5
```

Настоящий токен хранится только на сервере, **не в GitHub и не в чатах**. `API_ID`, `API_HASH`, `PHONE` и Telegram-сессия больше не нужны. Прежний `.env` автоматически не переписывается: замените старые параметры самостоятельно. Старый `data/archive.sqlite3` не мигрируется и не перезаписывается; новый архив — `data/veltrix.sqlite3`.

## Запуск на Windows

Установите [Python 3.11+](https://www.python.org/downloads/windows/) и Git. В PowerShell:

```powershell
git clone https://github.com/tehnofakt/Veltrix.git
cd Veltrix
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
.\.venv\Scripts\python.exe main.py
```

Для уже скачанного проекта остановите старую программу, выполните `git pull --ff-only` и повторно установите зависимости. Не копируйте `.env.example` поверх заполненного `.env` без необходимости.

## Запуск на Linux-сервере

```bash
git clone https://github.com/tehnofakt/Veltrix.git
cd Veltrix
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
nano .env
chmod 600 .env
.venv/bin/python main.py
```

Понадобится Python 3.11+ и пакет поддержки `venv` вашей системы. Запускайте от отдельного пользователя без прав root. Для постоянной работы настройте перезапуск процесса средствами сервера. Пример unit-файла systemd (замените пользователя и оба пути):

```ini
[Unit]
Description=Veltrix Telegram bot
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=veltrix
WorkingDirectory=/home/veltrix/Veltrix
ExecStart=/home/veltrix/Veltrix/.venv/bin/python -u /home/veltrix/Veltrix/main.py
Restart=on-failure
RestartSec=5
UMask=0077

[Install]
WantedBy=multi-user.target
```

Сохраните как `/etc/systemd/system/veltrix.service`, затем:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now veltrix
sudo systemctl status veltrix
```

Работает long polling: домен, HTTPS-сертификат и открытый входящий порт не нужны. Нужен исходящий доступ к Telegram API и серверу скачивания файлов. При запуске прежний webhook этого токена снимается **без удаления ожидающих обновлений**. Один токен должен обслуживаться одним экземпляром программы. Во время сетевого сбоя polling переподключается; недействительный токен и постоянные ошибки конфигурации требуют исправления владельцем.

## Как подключается пользователь

1. Находит вашего бота, нажимает **Start** и читает инструкцию о доступе и хранении данных.
2. Открывает **Настройки / Редактирование профиля → Чат-боты**, либо **Telegram для бизнеса → Чат-боты** в соответствующей версии клиента.
3. Выбирает вашего бота, разрешённые личные чаты и права на ответы и удаление входящих.
4. Отправляет `/status` в диалоге с Veltrix.
5. Ждёт нового сообщения в выбранной переписке. `/chats` покажет известный боту чат и его ID; там же можно использовать команды с точкой.

Пользователь может отозвать доступ через настройки Telegram. Изменение прав или отключение подключения прекращает его активные отправки. Настройки мута остаются в базе и начинают применяться при доступном подключении и нужных правах.

## Команды в диалоге с Veltrix

| Команда | Назначение |
| --- | --- |
| `/start` | Инструкция, включение или возобновление обработки. |
| `/connect` | Повторная инструкция подключения. |
| `/status` | Состояние обработки, подключения и прав. |
| `/chats` | До 30 последних известных чатов и их ID. |
| `/archive`, `/archive 2` | Входящие сообщения, включая удалённые, по 5 на странице. Собственные исходящие не архивируются. |
| `/mute ID`, `/unmute ID` | Управление мутом выбранного своего чата. |
| `/spam ID 10 привет` | Конечная отправка от имени своего подключённого аккаунта. |
| `/stopspam ID` | Остановка отправки в этом чате. |
| `.spam 10 тест`, `.spam forever тест` | Тест в диалоге с ботом, от имени бота. |
| `.stopspam` | Остановка теста. |
| `/help`, `.help` | Справка. |
| `/privacy` | Информация о доступе и хранении. |
| `/stop` | Приостановить архивирование, уведомления и свои отправки; данные остаются. |
| `/erase confirm` | Остановить обработку, удалить свой архив, очередь уведомлений, фотографии и настройки с сервера. |

## Где хранятся переписки

**Интерфейс архива — сам бот.** Физически данные находятся на вашем сервере в `data/veltrix.sqlite3`, фотографии — в `data/media/`. В GitHub и сторонние облачные хранилища программа их не отправляет. Уведомления и результаты `/archive` доставляются в обычный личный диалог пользователя с Veltrix, то есть также хранятся в облаке Telegram как сообщения этого диалога.

Владелец сервера технически имеет доступ к базе и файлам. Прикладного шифрования архива нет. Ограничьте доступ к папке `data`, диску и резервным копиям. Не обещайте пользователям сквозное шифрование или хранение исключительно на их устройствах. Информация о серверном хранении показывается в `/start` до подключения.

`/erase confirm` выполняет обычное удаление файлов и записей, не гарантированное стирание блоков диска или резервных копий. Уже доставленные в Telegram сообщения пользователь удаляет отдельно. Минимальная запись ID пользователя с флагом остановки остаётся, чтобы запоздалые события не возобновили архивирование. Само подключение следует отозвать в Telegram. После нового `/start` обработка может возобновиться. Автоматической очистки архива по сроку нет: владелец следит за местом на диске. Резервные копии делайте вне репозитория, остановив программу и скопировав всю папку `data`.

`.gitignore` исключает `.env`, `data`, базы SQLite, медиа, логи, Telegram-сессии и виртуальные окружения. Не добавляйте их через `git add -f`. Перед публикацией проверяйте `git diff --cached --name-only`.

## Проверки и честный статус

```powershell
.\.venv\Scripts\python.exe -m compileall -q main.py tests
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m pip check
```

Тесты используют реальные модели и диспетчер aiogram, временную SQLite-базу и имитацию сетевых ответов. Проверяются разделение пользователей, права, команды, отправка и остановка, ожидания Telegram, фотографии, удаление и редактирование, постоянная очередь уведомлений, очистка своих данных. Это **не проверка с настоящим токеном или подключённым аккаунтом**. Установка на ваш сервер и проверка через Telegram выполняются после настройки `.env`.

Ручная проверка перед приглашением пользователей: `/start` → подключение → `/status`; сообщение и фото со второго тестового аккаунта → `/archive`; изменение и удаление сообщения → уведомления; `.mute` → новое входящее сохраняется и удаляется без уведомления о собственном удалении; `.unmute`; `.spam 3 тест` и `.stopspam` в согласованном тестовом чате; отключение доступа → прекращение отправки.
